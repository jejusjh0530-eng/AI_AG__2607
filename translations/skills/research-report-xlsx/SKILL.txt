# 리서치 보고서 → XLSX 변환

## 이 스킬이 하는 일

주제가 주어지거나 사용자가 특정 파일을 가리키면, 이 스킬은 관련 내용을 수집하고, 하나 이상의 표 형태 시트로 정리한 뒤, 번들로 포함된 `scripts/build_spreadsheet.py` 생성기(`openpyxl` 기반)를 사용해 스타일이 적용된 `.xlsx` 워크북으로 렌더링합니다.

이 생성기는 `research-report-docx`의 `build_report.py`처럼 데이터 기반(data-driven) 방식입니다. 워크북의 시트 구성을 설명하는 JSON을 넘기면, 일관된 스타일링과 다음과 같은 "스마트" 스프레드시트 동작을 자동으로 처리해줍니다.

- **ID 열** — 모든 시트의 A열에 순차적인 `ID` 열이 자동으로 추가됩니다 (시트 데이터가 이미 ID/No/번호 같은 식별자 열로 시작하면 건너뜁니다).
- **제목/헤더 스타일** — 제목은 굵게(첫 번째 시트에만), 헤더 행은 메인 컬러 배경에 흰색 굵은 글씨로 표시됩니다.
- **인용구 열** — 헤더가 `quote`/`quotation`/`인용구`/`인용문`인 열은 이탤릭체로 표시됩니다.
- **본문 텍스트** — 일반 데이터 셀은 모두 10pt로 표시됩니다.
- **자동 차트** — 실제 숫자 데이터가 있는 열(성장률, 전년 대비 증감, 가격/수량 비교 등 — `"12.5%"` 같은 퍼센트 문자열도 자동으로 숫자로 변환됩니다)마다 차트가 자동 생성됩니다. 행 카테고리가 연도/월/분기 같은 시계열로 보이면 `LineChart`, 그렇지 않으면 `BarChart`가 선택됩니다. 실제 숫자가 충분하지 않은 열에는 차트가 생성되지 않으므로, 자리표시자/텍스트 전용 표는 차트 없이 그대로 유지됩니다.

차트 생성이 자동이기 때문에 직접 차트 종류를 고민할 필요가 없습니다 — 시각화하고 싶은 수치 비교를 명확한 헤더를 가진 별도의 열에 넣기만 하면 나머지는 생성기가 처리합니다.

## 어떤 모드에 해당하는지 판단하기

작업을 시작하기 전에 두 가지 트리거 중 어느 쪽에 해당하는지 파악하세요.

1. **주제 조사 모드** — 사용자가 주제/대상을 제시하고 이를 조사해서 스프레드시트로 전달받고 싶어하는 경우.
2. **파일 분석 모드** — 사용자가 특정 기존 파일을 언급하며 그 내용을 (새로운) 스타일이 적용된 스프레드시트로 만들어 달라는 경우.

두 모드는 서로 배타적이지 않습니다 — 사용자가 파일을 언급하면서 동시에 추가적인 웹 조사를 요청할 수도 있습니다. 상황에 맞게 판단하세요. JSON을 구성하는 단계 자체는 동일하며, 내용을 어디서 가져오는지만 다릅니다.

## 작업 순서

### 1. 필요 시 범위 확인

주제가 모호하거나, 사용자가 말한 파일이 어떤 파일인지 불명확하거나, 원하는 시트 구성이 명확하지 않다면, 본격적인 작업 전에 짧게 확인 질문을 합니다. 범위가 명확하고 단순한 요청이라면 과도하게 되묻지 않습니다.

### 2. 내용 수집

**주제 조사 모드:** `WebSearch`(그리고 유망한 출처에 대해서는 `WebFetch`)를 사용해 최신의 신뢰할 수 있는 정보를 수집합니다. 1차 출처와 최근 자료를 우선합니다. 별도의 열로 넣을 수 있는 수치(성장률, 전년/전분기 대비 증감, 연도·지역·브랜드·제품 간 가격/점유율 비교 등)를 적극적으로 찾으세요 — 이런 수치가 있어야 자동 차트 기능이 작동하므로, 본문 텍스트 안에 묻어두지 마세요. 실제로 참고한 출처 URL은 "Sources" 시트에 넣기 위해 기록해 둡니다.

**파일 분석 모드:** 먼저 언급된 파일을 읽습니다.
- **구조화된 데이터 파일** (`.xlsx`, `.csv`): 기존 헤더/행을 그대로 읽어옵니다(예: `openpyxl`이나 Python의 `csv` 모듈 사용). 이 모드의 목적은 데이터를 새로 만들어내는 것이 아니라, 기존 데이터에 ID 열·스타일·자동 차트를 적용해 다시 표현하는 것입니다. 원래의 열 이름과 값을 그대로 보존하고 숫자를 임의로 만들어내지 마세요.
- **비정형 문서** (`.pdf`, `.docx`, `.txt`, `.pptx` 등): 텍스트 내용을 읽거나 추출한 뒤, 웹 조사 때와 마찬가지로 구체적인 수치, 비교 데이터, 눈에 띄는 인용문을 뽑아냅니다. URL 대신 원본 파일명(관련이 있다면 페이지/섹션도)을 "Sources" 시트에 표시하세요.

사용자가 파일과 주제를 함께 제시했다면 두 가지를 결합하세요 — 파일 데이터를 주요 출처로 삼고, 부족한 부분이나 맥락은 웹 조사로 보완합니다.

### 3. 조사 결과를 JSON으로 구조화

아래 스키마에 맞춰 JSON 파일(예: 임시/스크래치 위치에)을 작성합니다.

```json
{
  "title": "보고서 제목",
  "subtitle": "한 줄 설명 또는 기간",
  "color": "#1F4E79",
  "sheets": [
    {
      "name": "Overview",
      "headers": ["Item", "Note"],
      "rows": [["Market size", "..."], ["Key player", "..."]]
    },
    {
      "name": "Growth Data",
      "headers": ["Year", "Revenue", "Growth Rate"],
      "rows": [["2023", 120000, "-"], ["2024", 138000, "15.0%"], ["2025", 151800, "10.0%"]]
    },
    {
      "name": "Sources",
      "headers": ["Source", "URL"],
      "rows": [["Site name", "https://..."]]
    }
  ]
}
```

작성 가이드:

- 각 시트는 `{"name", "headers", "rows"}` 형태이며, `rows`는 `headers` 순서에 맞는 리스트의 리스트입니다. 숫자는 일반 숫자 또는 퍼센트 문자열(`"12.5%"`)로 넣을 수 있고, 텍스트는 텍스트 그대로 둡니다.
- 시트 개수와 이름은 내용에 맞게 조정하세요. 위 Overview/Data/Sources 구조는 출발점일 뿐 고정된 템플릿이 아닙니다 — 단순한 요청은 시트 하나로 충분할 수도 있고, 풍부한 주제는 여러 데이터 시트가 필요할 수도 있습니다.
- 차트로 만들고 싶은 비교/성장 수치는 반드시 별도의 숫자 열에 넣고, 그 왼쪽에 카테고리 열(연도, 지역, 브랜드, 제품 등)을 두세요 — 생성기가 이 카테고리 열을 차트의 축 레이블로 사용합니다. 만약 "Growth Rate" 열이 아직 모든 행에서 자리표시자 `-`뿐이라면, 생성기는 이를 올바르게 인식해 차트를 생략하며 오류를 내지 않습니다.
- 시트에 자연스러운 인용/후기 열이 있다면 헤더를 `Quote`, `Quotation`, `인용구`, `인용문` 중 하나로 지정해 이탤릭으로 표시되게 하세요.
- 사용자가 특정 메인 컬러를 요청했다면 `"color"`에 해당 hex 코드를 넣고, 그렇지 않으면 생성기가 적절한 기본 네이비 컬러로 처리합니다.

### 4. 워크북 생성

다음을 실행합니다.

```bash
python "<skill-dir>/scripts/build_spreadsheet.py" --input findings.json --output "<topic>.xlsx"
```

사용자가 생성 시점에 컬러를 지정하면 JSON의 `"color"` 필드 대신(또는 이를 덮어써서) `--color "#RRGGBB"`를 전달합니다. 전체 옵션 목록은 `scripts/build_spreadsheet.py`를 참고하세요.

### 5. 파일 전달

사용자의 다른 생성 파일들이 위치한 곳에 결과물을 저장하고(불명확하면 물어보기), 사용자에게 위치를 안내합니다. 각 시트가 다루는 내용, 어떤 열이 자동으로 차트화되었는지(그리고 명확하지 않다면 다른 열은 왜 차트화되지 않았는지), 어떤 출처를 사용했는지를 간단히 요약해서 알려주어, 사용자가 내용을 신뢰하기 전에 직접 검토할 수 있게 합니다.

## 이런 구조인 이유

여기서 엑셀이 워드보다 갖는 진짜 가치는, 표가 단순히 서식이 적용된 텍스트가 아니라 기능하는 데이터라는 점입니다. 그래서 이 생성기도 `build_report.py`가 docx에 대해 그렇듯 스키마 기반(JSON 입력 → xlsx 출력)이지만, 스키마는 산문 형태가 아니라 표 형태이며, 스타일링 작업은 스프레드시트에 특히 필요한 요소들 — 안정적인 ID 열, 읽기 편한 본문 크기, 인용문을 위한 이탤릭체, 그리고 데이터가 실제로 뒷받침될 때만 나타나는 차트 — 에 집중되어 있습니다.

## 참고 사항

- 실행 환경에 `openpyxl`이 설치되어 있지 않다면 먼저 설치하세요 (`pip install openpyxl`).
- 시트 이름은 자동으로 정리되고 중복이 제거됩니다(엑셀은 `: \ / ? * [ ]` 문자를 허용하지 않고 이름을 31자로 제한합니다), 따라서 JSON에서 완벽하게 엑셀에 안전한 시트 이름을 고민할 필요는 없습니다.
- 사용자가 여러 시트 대신 단일 시트 스프레드시트를 요청하면 `"sheets"`에 항목을 하나만 넣으면 됩니다 — 스키마의 나머지 부분은 달라지지 않습니다.
- 현재 환경에서 웹 검색을 사용할 수 없거나(주제 모드) 언급된 파일을 읽을 수 없다면(파일 모드), 이를 명확히 알리고 데이터를 임의로 만들어내는 대신 사용 가능한 최선의 대안(기존 지식 활용, 또는 사용자에게 내용을 붙여넣어 달라고 요청)을 제안하세요.
