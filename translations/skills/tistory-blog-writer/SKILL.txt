# 티스토리 블로그 작성기

주제 하나를 실제로 사용자의 티스토리 블로그에 놓인 초안 글로 바꿉니다. 실제 타이핑과 클릭은 claude-in-chrome 브라우저 확장이 수행하며, 단순히 채팅으로 문서를 건네는 것이 아닙니다.

## 이런 구조인 이유

티스토리 글 작성은 서로 반대 방향으로 실수하기 쉬운 두 단계로 나뉩니다: 조사/작성 단계(잘못하면 글이 부정확하거나 부실해짐)와 발행 단계(잘못하면 사용자가 승인하지 않은 내용이 공개되거나, 에이전트가 로그인 폼에 자격 증명을 입력하게 됨). 이 스킬은 이 두 단계를 확실한 체크포인트로 분리합니다: 사용자가 초안을 명시적으로 검토하고 공개/비공개를 명시적으로 선택하기 전까지는 그 무엇도 사용자 본인 외에는 보이지 않습니다.

## 작업 흐름

### 1단계: 주제 확인

사용자의 주제가 모호하거나 여러 의미로 해석될 수 있다면(범위가 넓은 주제, "요즘"처럼 애매한 기간 등) 짧게 확인 질문을 하세요. 명확하고 범위가 정해진 주제라면 바로 진행합니다 — 과도하게 되묻지 마세요.

### 2단계: 주제 조사

`WebSearch`/`WebFetch`를 사용하거나, 사용자가 특별히 브라우저 기반 조사를 원한다면 claude-in-chrome(`navigate`로 검색엔진 접속, `get_page_text`로 결과 읽기)을 사용하세요. 여러 개의 구체적이고 최신인 논점을 뒷받침할 만큼 충분한 자료를 모으되, 이 글은 학술 보고서가 아니라 블로그 글이므로 방대한 목록보다는 잘 설명된 몇 가지 발견에 집중하세요. 실제로 사용한 출처를 기록해 두세요 — 이 워크플로우의 티스토리 글은 정식 참고문헌이 아니라 짧은 출처 한 줄로 마무리됩니다.

### 3단계: 보고서가 아니라 블로그 스타일로 작성

블로그 독자는 훑어 읽습니다. 초안은 다음과 같은 구조로 작성하세요:
- 짧고 구체적인 제목("AI 소식" 같은 밋밋한 제목은 지양)
- 지금 왜 이 이야기가 중요한지를 짚어주는 한두 문장의 도입부
- 3~6개의 번호 매기거나 소제목을 단 섹션, 각각 짧은 문단으로(글 벽이나 표는 지양)
- 논점을 정리하는 짧은 마무리 문단(앞으로 지켜볼 지점, 왜 중요한지)
- 마지막에 한 줄짜리 출처 표기

사용자가 요청한 언어로 작성하세요. 문단은 대화체로 — 이 콘텐츠는 기업용 산출물이 아니라 공개 또는 준공개 블로그에 올라갑니다.

### 4단계: 티스토리를 열고 글쓰기 화면으로 이동

claude-in-chrome 도구가 아직 로드되지 않았다면 한 번의 `ToolSearch` 호출로 로드하세요 (`select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__find,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__browser_batch,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__tabs_close_mcp`). 그런 다음:

1. `tabs_context_mcp`를 `createIfEmpty: true`로 호출해 탭을 확보합니다.
2. `https://www.tistory.com`으로 `navigate`합니다.
3. 이미 로그인되어 있는지 확인하세요 — 페이지 텍스트나 스크린샷에서 사용자의 블로그 이름/"글쓰기" 버튼이 보이는지, 아니면 로그인 안내가 보이는지 확인합니다.
4. **로그인되어 있지 않다면: 멈추고 사용자에게 브라우저 창에서 직접 로그인해 달라고 요청하세요.** 사용자가 아이디/비밀번호를 알려주더라도 절대 대신 입력하거나 OAuth/소셜 로그인 단계를 대신 완료하지 마세요 — 자격 증명 입력은 어떤 경우에도 금지됩니다. 사용자가 로그인을 완료했다고 확인해 줄 때까지 기다린 뒤 다시 확인하세요.
5. 로그인이 확인되면 "글쓰기" 링크를 `find`로 찾아 클릭합니다(보통 `https://<블로그이름>.tistory.com/manage/newpost`로 글쓰기 화면이 새 탭에 열립니다).

### 5단계: 제목과 본문 채우기

티스토리 에디터는 리치 텍스트 필드입니다: 제목 placeholder를 클릭하고 입력하면 제목이 설정되고, 그 아래 본문 영역을 클릭하고 입력하면 본문이 채워집니다. 문자 그대로의 `\n`을 붙여넣으려 하지 말고, 섹션 사이 문단 구분은 `computer`의 `action: "key"`로 `Return` 키를 눌러 만드세요.

클릭/입력/키 입력 시퀀스는 `browser_batch`로 묶어서 처리하세요 — 작은 동작이 많아서 하나씩 처리하면 느리고 턴을 많이 소모합니다. 이후 `screenshot`으로 제목과 시작 문단이 제대로 들어갔는지 확인하세요. 본문 끝부분만 보이는 화면이라면 위로 스크롤해서 확인하세요.

사용자가 특별히 요청하지 않는 한 대표이미지와 카테고리 설정은 생략하세요 — 설정하지 않는 것이 일반적이고 마찰이 적은 기본값이며, 티스토리는 저장이나 발행에 이 둘을 요구하지 않습니다.

### 6단계: 임시저장으로 저장 — 아직 발행하지 않음

"임시저장"을 클릭하세요. 이는 먼저 묻지 않고 진행해도 안전합니다: 비공개이고 되돌릴 수 있는 초안 저장이지 발행이 아닙니다. 저장이 잘 됐는지 확인하세요(보통 버튼에 저장 개수가 표시됩니다. 예: "임시저장 | 1").

### 7단계: 무엇이든 공개되기 전에 명시적 승인 받기

발행은 — 비공개 상태로라도 — 사용자 계정에 실제 게시물을 만드는 행위이므로 요청 없이 진행해서는 안 됩니다. 임시저장 후, 무엇을 작성했는지(제목 + 섹션 한 줄 요약) 사용자에게 알리고 다음에 무엇을 원하는지 물어보세요: 초안으로만 남길지, 지금 발행할지, 직접 수정할지. 임의로 판단하지 말고 `AskUserQuestion`을 사용하세요.

### 8단계: 발행을 원한다면 공개/비공개 확인

이 확인만큼은 이 워크플로우에서 사용자가 명시적으로 요구한 사항이므로 절대 생략하거나 임의로 정해서는 안 됩니다. "완료"를 클릭해 발행 대화상자를 열고, 사용자에게 공개(공개), 공개(보호)(비밀번호 보호), 비공개(비공개) 중 무엇을 원하는지 직접 물어보세요 — 대화상자의 라디오 버튼이 이 선택지에 그대로 대응하며, 저장 버튼의 표시 문구도 선택에 따라 바뀝니다(예: "비공개 저장", "발행"). 사용자가 고른 옵션을 선택하고 해당 버튼을 클릭하세요.

### 9단계: 결과 보고

글의 최종 상태(초안만 존재 / 비공개 저장됨 / URL과 함께 공개 발행됨)를 사용자에게 알리고, 이 스킬이 열었던 claude-in-chrome 탭 중 사용자가 계속 열어두길 원하지 않는 것은 정리하세요(`tabs_close_mcp`).

## 참고 사항

- claude-in-chrome 도구가 지연 로드 상태라면, 하나씩이 아니라 한 번의 `ToolSearch` 호출로 모두 로드하세요(4단계 참고).
- 로그인 대기나 에디터 조작이 막힌 것처럼 보이면(요소를 찾지 못하거나 2~3회 시도 후에도 페이지가 반응하지 않으면), 계속 재시도하지 말고 멈춰서 상황을 설명하세요 — 이는 브라우저 자동화에 대한 일반 지침(막다른 길을 피하라)과 동일합니다.
- 현재 환경에서 웹 검색/브라우저 조사를 사용할 수 없다면 이를 명시적으로 밝히고, 기존 지식만으로 작성하는 것을 제안하되 최신 정보가 아닐 수 있음을 알리세요.
