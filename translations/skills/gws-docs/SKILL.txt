# gws-docs

## 이 스킬이 하는 일

로컬 파일이 아니라 실제 Google Docs 문서를 이 프로젝트에 이미 인증되어 있는 `gws` CLI(Google Workspace CLI)를 사용해 사용자의 Google 드라이브에 직접 생성합니다. "X에 대한 구글 문서 만들어줘"라는 요청에서 나올 수 있는 두 가지 상황을 모두 처리합니다.

- **처음부터 조사**: 사용자가 주제만 주고 다른 자료는 없는 경우. 다른 보고서 작성 때와 동일하게 조사한 뒤, 그 조사 결과를 새 문서에 작성합니다.
- **기존 자료 정리**: 사용자가 이미 내용(붙여넣은 텍스트, 대화 중 앞서 나온 메모, 로컬 파일)을 가지고 있고 이를 제대로 구조화된 Google 문서로 바꾸고 싶어하는 경우. 이때는 조사를 건너뛰고 이미 있는 내용을 정리합니다.

어느 쪽이든 결과물은 사용자가 자신의 드라이브에서 열고, 편집하고, 공유할 수 있는 실제 Google Docs 링크입니다 — 첨부 파일이 아닙니다.

## 시작하기 전: gws 인증 확인

Docs API에는 `documents` 스코프(그리고 CLI가 파일을 생성할 수 있도록 `drive`/`drive.file` 스코프도)가 필요한데, 이는 Gmail 전용처럼 다른 목적으로 설정된 `gws` 연결이 가진 스코프보다 넓은 범위입니다. 먼저 다음을 실행하세요.

```bash
npx --yes @googleworkspace/cli auth status
```

그리고 `"scopes"`에 `https://www.googleapis.com/auth/documents`가 있는지 확인하세요. 없다면 아래 생성 단계에서 (도움이 되는 메시지 없이) 인증 오류(exit code 2)로 실패하므로, 미리 확인하는 편이 좋습니다. 스코프를 추가하려면:

```bash
npx --yes @googleworkspace/cli auth login --services docs,drive,gmail,calendar,forms
```

이 명령은 브라우저 동의 URL을 엽니다. 현재 세션에서 브라우저 자동화 도구(예: Playwright MCP)를 사용할 수 있다면 직접 동의 절차를 진행해도 되고, 그렇지 않다면 URL을 사용자에게 공유해 이 프로젝트의 다른 `gws auth login` 절차와 동일한 방식으로 완료해 달라고 요청하세요. `docs`/`drive`와 함께 이미 사용 중인 다른 서비스(`gmail`, `calendar`, `forms`)도 같은 로그인 요청에 포함시키면, 사용자가 이전에 승인했던 스코프가 새 토큰에서 조용히 빠지는 일 없이 하나의 통합된 토큰으로 유지됩니다.

## 작업 순서

1. **조사할지, 정리할지 판단.** 사용자가 뒷받침 자료 없이 주제만 줬다면, 다른 보고서를 쓸 때처럼 `WebSearch`(그리고 유망한 출처에는 `WebFetch`)로 조사합니다 — 한 단락이 아니라 실제로 여러 섹션을 뒷받침할 만큼 충분히 모으고, 마지막의 "출처(Sources)" 섹션을 위해 출처 URL을 기록해 둡니다. 사용자가 이미 내용을 줬다면 바로 구조화 단계로 넘어갑니다 — 사용자가 이미 준 내용을 다시 조사하는 것은 시간 낭비이고 사용자가 실제로 말한 내용과 어긋날 위험이 있습니다.

2. **내용을 블록 단위로 구성.** Docs API는 마크다운이 아니라 위치 인덱스 기반 편집만 이해하므로, 이 스킬에 포함된 스크립트는 대신 간단한 블록 목록을 받습니다. 임시 JSON 파일로 작성하세요.

   ```json
   [
     {"type": "heading1", "text": "문서 제목"},
     {"type": "paragraph", "text": "도입 단락..."},
     {"type": "heading2", "text": "섹션 이름"},
     {"type": "paragraph", "text": "..."},
     {"type": "bullet", "text": "첫 번째 항목"},
     {"type": "bullet", "text": "두 번째 항목"},
     {"type": "heading2", "text": "출처"},
     {"type": "bullet", "text": "https://..."}
   ]
   ```

   사용 가능한 `type`: `heading1`, `heading2`, `heading3`, `paragraph`, `bullet`. 연속된 `bullet` 블록은 자동으로 하나의 글머리 기호 목록으로 묶입니다 — 직접 그룹화할 필요가 없습니다. 섹션 개수와 이름은 주제에 맞게 구성하면 되고, 고정된 템플릿은 없습니다. 첫 항목을 `heading1` 블록으로 두면 문서 본문 안에도 보이는 제목이 생깁니다(다음 단계의 `--title`로 지정하는 드라이브 파일명과는 별개입니다).

3. **문서 생성.** 번들로 포함된 스크립트를 실행하세요. 이 스크립트는 `gws docs documents create`로 빈 Google 문서를 만든 뒤, 텍스트/제목 스타일/글머리 기호 서식을 하나의 `batchUpdate` 호출로 한 번에 적용합니다.

   ```bash
   python "<skill-dir>/scripts/create_google_doc.py" --title "문서 제목" --content blocks.json
   ```

   실행하면 `{"documentId": "...", "url": "https://docs.google.com/document/d/.../edit"}`가 출력됩니다. 문서는 사용자 드라이브 루트(내 드라이브)에 생성됩니다 — 이 스킬은 폴더로 옮기거나 공유 설정을 변경하지 않습니다. 사용자가 둘 중 하나를 원한다면 이는 별도의 명시적인 단계입니다. 무언가의 권한을 바꾸는 일은 임의로 추측해서 할 만한 기본 동작이 아니기 때문입니다.

4. **링크 전달.** 스크립트 출력의 `url`을 사용자에게 전달하고, 문서가 다루는 내용을 한두 줄로 요약해서 알려주세요(조사를 했다면 어떤 출처를 참고했는지도). 사용자가 내용을 신뢰하기 전에 직접 검토할 수 있도록 하기 위함입니다.

## 원시 batchUpdate 호출 대신 번들 스크립트를 쓰는 이유

Google Docs의 `batchUpdate` 요청들(`insertText`, `updateParagraphStyle`, `createParagraphBullets` 등)은 모두 문자 인덱스로 문서 위치를 지정하는데, 어떤 편집이든 적용되는 순간 그 이후의 모든 인덱스가 밀립니다. 이를 손으로 직접 계산하는 것 — 특히 여러 번의 `insertText` 호출에 걸쳐서 — 은 매번 직접 다시 하기보다는 스크립트가 대신 처리해야 할 만큼 까다롭고 실수하기 쉬운 작업입니다. `scripts/create_google_doc.py`는 문서 전체 텍스트를 단 한 번의 `insertText` 호출로 삽입하고, 그 텍스트를 조립하는 과정에서 추적해 둔 오프셋으로 모든 스타일/글머리 기호 범위를 계산함으로써 인덱스가 밀리는 문제를 아예 피합니다 — 그래서 범위가 꼼꼼히 세어서 맞는 게 아니라 애초에 구조적으로 맞습니다.

이 스크립트는 여러분이 직접 호출할 수도 있는 것과 동일한 `gws` CLI(`docs documents create`, `docs documents batchUpdate`)를 그대로 호출하며, 요청을 구성하는 부분만 대신 처리해 줍니다. 블록 스키마가 다루지 않는 것(표, 이미지, 링크, 텍스트 색상 등)이 필요하면 `gws docs documents batchUpdate`를 직접 호출해 추가 요청 타입을 사용하세요 — 전체 요청 형태는 `gws schema docs.documents.batchUpdate --resolve-refs`를 참고하세요.

## 참고 사항

- 이 스크립트는 (플랫폼 기본 셸이 아니라) 명시적으로 `bash`를 통해 명령을 실행합니다. 따옴표와 비ASCII 텍스트가 포함된 JSON 페이로드가 손상 없이 그대로 전달되도록 하기 위해서입니다 — 이는 특히 Windows에서 중요합니다. Windows에서는 `npx`가 `.cmd` 파일로 해석되는데, 이런 종류의 인자를 `CreateProcess`도 `cmd.exe`도 깔끔하게 처리하지 못합니다. 이는 호출하는 입장에서는 신경 쓸 필요 없이 투명하게 처리되므로, 위에 나온 대로 스크립트를 실행하기만 하면 됩니다.
- `gws auth status`에 `documents`/`drive` 스코프가 있는 것으로 나오는데도 호출이 인증 오류로 실패한다면, 이 스킬이 필요로 하는 스코프가 알려지기 전에 더 좁은 스코프 집합으로 토큰이 발급됐을 수 있습니다 — 이 문서 맨 위의 `auth login` 명령을 전체 서비스 목록으로 다시 실행하세요.
- 현재 환경에서 조사 경로에 필요한 웹 검색을 사용할 수 없다면 이를 명확히 알리고, 기존 지식만으로 문서를 작성하는 대안을 제안하되 최신 정보가 반영되지 않을 수 있음을 함께 안내하세요.
