# 리서치 보고서 → DOCX 변환

## 이 스킬이 하는 일

주제가 주어지면 웹에서 조사를 수행하고, 조사 결과를 명확한 보고서 구조로 정리한 뒤, 번들로 포함된 `scripts/build_report.py` 생성기(`python-docx` 기반)를 사용해 스타일이 적용된 `.docx` 파일로 렌더링합니다.

이 생성기는 데이터 기반(data-driven) 방식입니다. 보고서 내용을 요약한 JSON을 넘기면, 폰트/크기/컬러/페이지 번호 등 일관된 스타일링을 알아서 처리해주므로, 워드 서식이 아니라 조사와 글쓰기 자체에 집중할 수 있습니다.

## 작업 순서

1. **필요 시 범위 확인.** 주제가 모호하거나 여러 의미로 해석될 수 있다면(예: 어떤 산업, 어떤 기간, 어떤 국가/시장인지), 조사를 시작하기 전에 사용자에게 짧게 확인 질문을 합니다. 범위가 명확하고 단순한 주제라면 과도하게 되묻지 않습니다.

2. **주제 조사.** `WebSearch`(그리고 유망한 출처에 대해서는 `WebFetch`)를 사용해 최신의 신뢰할 수 있는 정보를 수집합니다. 1차 출처와 최근 자료를 우선합니다. 개요, 구체적인 몇 가지 포인트/발견 사항, 표로 정리할 만한 수치 등 여러 개의 개별 섹션을 뒷받침할 수 있을 만큼 충분히 자세하게 수집합니다. 실제로 참고한 출처 URL 목록을 별도로 기록해 두었다가, 보고서 마지막의 "출처(Sources)" 섹션에 넣어 독자가 내용을 검증할 수 있게 합니다.

3. **조사 결과를 JSON으로 구조화.** 아래 스키마에 맞춰 JSON 파일(예: 임시/스크래치 위치에)을 작성합니다.

   ```json
   {
     "title": "보고서 제목",
     "subtitle": "한 줄 설명 또는 기간",
     "color": "#1F4E79",
     "sections": [
       {"heading": "1. 개요", "paragraphs": ["..."]},
       {"heading": "2. 주요 발견 사항", "bullets": ["...", "..."]},
       {"heading": "3. 데이터", "table": {"headers": ["...", "..."], "rows": [["...", "..."]]}},
       {"heading": "4. 출처", "bullets": ["https://...", "https://..."]}
     ]
   }
   ```

   각 섹션은 `paragraphs`, `bullets`, `table`을 자유롭게 조합할 수 있습니다 — 내용에 맞는 것만 포함하면 됩니다. 섹션 개수와 이름은 주제에 맞게 조정하세요. 위 4개 섹션 구조는 출발점일 뿐 고정된 템플릿이 아닙니다. 사용자가 특정 메인 컬러를 요청했다면 `"color"`에 해당 hex 코드를 넣고, 그렇지 않으면 생성기가 적절한 기본 네이비 컬러로 처리합니다.

4. **문서 생성.** 다음을 실행합니다.

   ```bash
   python "<skill-dir>/scripts/build_report.py" --input findings.json --output "<topic>.docx"
   ```

   사용자가 생성 시점에 컬러를 지정하면 JSON의 `"color"` 필드 대신(또는 이를 덮어써서) `--color "#RRGGBB"`를 전달합니다. 전체 옵션 목록은 `scripts/build_report.py`를 참고하세요 — 전체 문서에 맑은 고딕 폰트, 제목 40pt, 섹션 제목 26pt, 본문/불릿 텍스트 20pt, 표 텍스트 16pt를 적용하고, 표 헤더 행은 메인 컬러로 음영 처리합니다.

5. **파일 전달.** 사용자의 다른 생성 문서들이 위치한 곳에 결과물을 저장하고(불명확하면 물어보기), 사용자에게 위치를 안내합니다. 사용자가 내용을 신뢰하기 전에 직접 검토할 수 있도록, 보고서가 다루는 내용과 사용한 출처를 간단히 요약해서 알려줍니다.

## 이런 구조인 이유

워드 문서는 CSS 스타일의 픽셀 단위 크기 지정을 지원하지 않습니다 — `python-docx`는 포인트(pt) 단위로 동작하므로, 여기서의 크기는 일반적인 워드 관례에 맞춰 pt로 지정됩니다. 생성기를 스키마 기반(JSON 입력 → docx 출력)으로 유지하면, 보고서마다 스크립트를 수정하지 않아도 동일한 스타일링 로직이 모든 주제에 그대로 적용되고, 매번 달라지는 것은 조사 내용뿐입니다.

## 참고 사항

- 실행 환경에 `python-docx`가 설치되어 있지 않다면 먼저 설치하세요 (`pip install python-docx`).
- 사용자가 다른 구조(예: 표 없이, 또는 요약만 있는 보고서)를 요청하면, JSON의 `sections` 배열만 그에 맞게 구성하면 됩니다 — 스크립트는 특정 섹션 개수나 이름을 요구하지 않습니다.
- 현재 환경에서 웹 검색을 사용할 수 없다면 이를 명확히 알리고, 기존 지식만으로 보고서를 작성하는 대안을 제안하되 최신 정보가 반영되지 않을 수 있음을 함께 안내하세요.
