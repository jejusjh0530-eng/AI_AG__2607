# Canva 디자인 워크플로우

사용자가 요청하지 않은 것이 만들어지는 일 없이, 주제를 승인된 완성 Canva 디자인으로 바꿔줍니다. 이 워크플로우에는 두 개의 강제 승인 지점이 있습니다 — 컨셉 승인, 그리고 최종 저장 승인 — 두 지점을 모두 통과하기 전까지는 사용자의 Canva 계정에 아무것도 생성되지 않습니다.

## 이 워크플로우가 중요한 이유

Canva의 `generate-design` 도구는 호출 즉시 실제 디자인 후보를 생성합니다 — 매 호출마다 지연 시간이 발생하고, 실제 디자인으로 전환되면 계정에 남는 부수 효과가 생깁니다. 주제에서 곧바로 생성된 디자인으로 건너뛰면 방향이 어긋난 결과물이 나올 위험이 있고, 그러면 사용자는 이를 설명하고 다시 만들게 해야 합니다. 이 워크플로우는 비용이 적고 되돌리기 쉬운 부분(텍스트 컨셉 아이디어)을 비용이 크고 상태를 남기는 부분(실제 생성) 앞에 배치해서, 사용자가 항상 "결정을 승인"하는 입장이지 "실수를 바로잡는" 입장이 되지 않도록 합니다.

## 1단계: 주제와 범위 확인

무언가를 제안하기 전에 아래를 확보하세요:
- **주제** — 디자인이 무엇에 관한 것인지/무엇을 위한 것인지.
- 요청에 이미 암시된 다른 정보(대상 독자, 톤, 브랜드, 반드시 포함할 텍스트/이미지). 사용자가 이미 알려준 세부사항은 다시 묻지 마세요.

주제 자체가 너무 모호해서 컨셉을 구분할 수 없다면(예: 그냥 "마케팅") 명확화 질문을 하나 하세요. 그렇지 않다면 바로 진행하세요 — 컨셉 단계에서는 아직 작업물 종류가 필요하지 않으므로 여기서 묻지 마세요.

## 2단계: 어울리는 템플릿이 있는지 확인

커스텀 컨셉을 제안하기 전에, Canva에 해당 주제와 어울리는 브랜드 템플릿이 이미 있는지 확인하세요 — 어울리는 템플릿에서 시작하면 처음부터 생성하는 것보다 빠르고 대개 더 완성도 높은 디자인이 나옵니다. 주제를 `query`로 하여 `search-brand-templates`를 호출하세요.

- **좋은 매칭이 있다면**, 사용자에게 보여주고(이름, 썸네일, `create_url`) 커스텀 컨셉 대신 이 템플릿으로 시작할지 물어보세요. 사용자가 수락하면: 3단계(커스텀 컨셉)와 5단계(작업물 종류 확인 — 템플릿이 이미 형식을 고정함)를 건너뛰고 바로 6단계로 이동하여, `generate-design` / `create-design-from-candidate` 대신 `create-design-from-brand-template`을 사용하세요. 템플릿이 자동채우기(autofill)를 지원한다면(`get-brand-template-dataset`로 확인) 템플릿으로 디자인을 만들기 전에 필드 값을 사용자와 함께 확정하세요.
- **좋은 매칭이 없거나, 사용자가 커스텀 디자인을 선호한다면**, 그 사실을 간단히 알리고 3단계로 정상 진행하세요 — 컨셉 단계를 건너뛰기 위해 맞지 않는 템플릿 매칭을 억지로 밀어붙이지 마세요.

## 3단계: 디자인 컨셉을 최소 3가지 제안 — 텍스트만, 도구 호출 없음

주제를 바탕으로 서로 다른 디자인 컨셉 제안을 최소 3가지 작성하세요. 각 컨셉은 몇 줄로 방향을 설명해야 합니다: 비주얼 무드/스타일, 색상 방향, 레이아웃 아이디어, 그리고 기울이는 메시지/앵글. 세 가지가 서로 실제로 다르게 만드세요(예: 미니멀/기업형 vs. 대담/발랄 vs. 사진 중심/에디토리얼) — 사용자가 단순한 겉모습 변형이 아니라 실제 방향을 선택하도록 하기 위해서입니다.

**이 단계에서는 `generate-design`이나 다른 어떤 Canva 생성 도구도 호출하지 마세요.** 컨셉은 사용자가 반응할 수 있는 순수 텍스트 제안입니다 — 이 단계에서 Canva 도구를 호출하면 사용자가 방향을 승인하기도 전에 실제 디자인이 만들어지는데, 이는 이 워크플로우가 막으려는 바로 그 상황입니다.

컨셉을 명확히 라벨링해서(컨셉 A/B/C…) 제시하고, 사용자에게 하나를 선택하거나 조정/새로운 방향을 요청하도록 하세요.

## 4단계: 컨셉 승인 게이트

사용자가 컨셉 하나를 명시적으로 선택하기 전까지는 다음 단계로 진행하지 마세요. 변경을 요청하면 수정해서 다시 제시하고, 세 가지 모두 거절하면 거절된 것을 재사용하지 말고 새로운 세트를 제안하세요. 침묵이나 모호한 답변은 "아직 승인되지 않음"으로 간주하세요 — 추측하지 말고 다시 물어보세요.

## 5단계: 작업물(결과물) 종류 확인

컨셉이 승인되면 사용자가 실제로 무엇을 만들고 싶어하는지 확인하세요 — 이는 `generate-design`의 `design_type`에 대응됩니다(예: `poster`, `instagram_post`, `presentation`, `card`, `flyer`, `logo`, `doc` 등). 승인된 컨셉이 이미 명확한 형식을 암시한다면 그것을 제안하고 사용자에게 확인만 받으세요 — 전체 목록에서 아무 맥락 없이 고르게 하지 마세요. 정말로 열려있는 경우라면 직접 물어보세요.

컨셉만으로는 답이 나오지 않는, `generate-design`에 필요한 범위 정보도 확인하세요 — 예: 발표자료 분량(짧게/균형/상세), 브랜드 키트 사용 여부(`list-brand-kits`, 사용자가 브랜드에 맞춘 결과를 원할 때만).

## 6단계: 디자인 생성 및 초안 저장

2단계에서 사용자가 매칭된 템플릿을 선택했다면, 이 단계의 `generate-design` 경로는 완전히 건너뛰세요: 대신 `brand_template_id`(및 확정된 자동채우기 필드 값)로 `create-design-from-brand-template`을 호출한 뒤 바로 7단계로 이동하세요 — 이 경우 고를 후보가 없습니다.

그렇지 않다면, 커스텀 컨셉 경로를 따르세요:

1. 5단계의 `design_type`과, 3단계에서 승인된 컨셉 설명 전체 + 주제를 담은 `query`로 `generate-design`을 호출하세요 — 이 도구는 대화 맥락을 기억하지 못하므로 매번 관련 내용을 전부 포함해야 합니다.
2. 후보가 즉시 반환되지 않으면 반환된 `job_id`로 `get-design-candidates`를 통해 폴링하세요.
3. 결과 후보 썸네일을 사용자에게 보여주세요. 여러 개라면 사용자가 직접 고르게 하세요 — 조용히 첫 번째를 기본값으로 쓰지 마세요.
4. 선택된 후보를 `create-design-from-candidate`(`job_id` + `candidate_id`)로 실제 저장된 디자인으로 전환하세요. 이것이 "초안 저장" 단계입니다 — 이제 디자인이 사용자의 Canva 계정에 실제로 존재합니다.

## 7단계: 검토용으로 초안 공유

새 `design_id`로 `get-design`을 호출해 편집/보기 URL을 얻고, 사용자가 Canva에서 직접 검토할 수 있도록 그 링크를 전달하세요. 확정 전에 수정을 원하면 `start-editing-transaction` → `perform-editing-operations` → `commit-editing-transaction` 순서를 사용하되(해당 도구 자체의 요구사항에 따라 커밋 호출 전 반드시 사용자의 명시적 승인을 받으세요), 업데이트된 썸네일/링크를 다시 공유하고 다시 확인을 받으세요.

이 단계를 최종 저장으로 취급하지 마세요 — 아직 사용자가 검토 중인 초안입니다. 사용자가 확정하기 전까지는 아무것도 내보내거나 폴더에 정리하지 마세요.

## 8단계: 최종 승인 시 — PNG로 내보내고 정리

사용자가 저장/확정을 명시적으로 승인한 뒤에만:

1. `design_id`로 `get-export-formats`를 호출해 PNG가 지원되는지(그리고 어떤 페이지에서 지원되는지) 확인하세요. 이 작업물 종류에서 PNG가 정말로 지원되지 않는다면, 다른 포맷으로 조용히 대체하지 말고 사용자에게 명확히 알리세요 — 추측하지 마세요.
2. `format.type: "png"`로 `export-design`을 호출하고 결과 다운로드 URL을 사용자에게 공유하세요.
3. 디자인을 사용자의 Canva 계정 내 `canva/<주제>` 폴더로 정리하세요:
   - 최상위 `canva` 폴더 찾기 또는 생성: `search-folders`(query `"canva"`, ownership `owned`)로 찾고, 없으면 `parent_folder_id: "root"`로 `create-folder`.
   - 그 안의 `<주제>` 하위 폴더 찾기 또는 생성: `canva` 폴더에 대해 `item_types: ["folder"]`로 `list-folder-items`를 호출해 이름이 일치하는 폴더가 있는지 확인(주제 문자열은 먼저 폴더명으로 쓸 수 있게 정리), 없으면 해당 `canva` 폴더를 `parent_folder_id`로 하여 `create-folder`.
   - `move-item-to-folder`로 디자인을 그 하위 폴더로 이동.
4. 사용자에게 다음을 포함해 확정 안내: Canva 폴더 위치, 디자인의 편집/보기 링크, PNG 다운로드 링크.

## 예외 상황 처리

- **사용자가 제안된 컨셉을 모두 거절**: 최소 3가지의 새로운 세트를 제안하세요 — 이미 거절된 것은 재사용하지 말고, 구체적으로 무엇이 맞지 않았는지 물어서 다음 세트가 실제로 달라지도록 하세요.
- **초안 저장(7단계) 후 사용자가 수정을 원함**: 편집 트랜잭션 도구를 사용하고, 커밋 전에 승인을 받은 뒤 다시 공유하고 다시 최종 승인을 요청하세요 — 사용자가 아예 다른 컨셉을 원하지 않는 한 처음부터 다시 생성하지 마세요.
- **어울리는 템플릿을 찾지 못함(2단계)**: 여기서 멈추지 마세요 — 좋은 템플릿 매칭을 찾지 못했다고 간단히 알리고 바로 커스텀 컨셉 제안으로 넘어가세요.
- **어울리는 템플릿이 있지만 사용자가 그래도 커스텀 컨셉을 원함**: 그 선택을 존중하고 3단계로 진행하세요 — 찾은 템플릿은 어디까지나 제안이지 강제 사항이 아닙니다.
- **선택한 작업물 종류에서 PNG 미지원**: 이를 사용자에게 알리고 어떻게 진행할지 물어보세요(다른 내보내기 포맷, 또는 다른 작업물 종류) — PNG가 아닌 다른 것을 조용히 내보내지 마세요.
- **세션 간 동일 주제 재사용**: `canva/<주제>` 폴더가 이미 존재하면 재사용하세요 — 같은 주제에 대해 이름이 살짝 다른 중복 폴더를 만들지 마세요.
- **여러 페이지로 구성된 디자인**: 내보내기 시 페이지당 PNG 1개가 생성됩니다 — 링크 하나만이 아니라 몇 개의 파일을 받게 되는지 사용자에게 알려주세요.
